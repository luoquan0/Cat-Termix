# Cat-Termix 2.9.2-cat-termix.18 — 管理员插件权限中心

**已发布：2026-10-12 13:49 UTC。** 本版针对 v17 Local Agent sudo 权限开通时缺少网页授权入口的问题。正式双架构镜像和软件更新 `ai-dev` 均已验证；没有直接修改用户的 2244 服务器。

## 修复内容

- **管理员设置 → 插件权限中心**：展示插件所声明的核心能力，以及已批准/未批准状态；支持按插件名称、ID 或能力搜索。
- 支持单独批准、撤销并刷新插件能力。调用已有的登录管理员 API，要求 `admin.plugins.manage`，授权写入数据库并由后端及时失效权限缓存。
- `ssh:sudo` 等 **Critical** 能力必须通过明确的风险确认弹窗才能批准；授权后再次从后端读取确认，不进行未经确认的乐观展示。
- 失败时保留原状态并显示错误，管理员可刷新复查。未启用插件不能通过该界面获得新增授权，但既有授权仍可撤销。
- 保留原设备的 `sudo:execute` 与 `jobs:execute` 单独审批，不能仅通过设备勾选跳过插件的 `ssh:sudo` 安全门禁。**本版不会自动批准 `ssh:sudo`**。
- 新增 API 路径、Critical 二次确认、授权、撤销和错误状态回归测试；保留此前的 AI、SSH、ARM64 更新器、代理输入与聊天持久化行为。

## 更新后启用 sudo

1. 备份数据卷、安排连接维护窗口，在 **管理员设置 → 软件自动更新** 使用 `ai-dev` 更新到 v18。更新会重启并中断现有 SSH 连接。
2. 用拥有 `admin.plugins.manage` 权限的管理员账号进入 **管理员设置 → 插件权限中心**，展开 **Local Agent**，找到 `ssh:sudo`，点击 **批准**，阅读警告后确认。
3. 在 **本地 Agent → 已配对设备 → 编辑权限** 为可信设备同时保留 `jobs:execute` 与 `sudo:execute`，并限制该设备能访问的主机。**不需要重新配对设备**。
4. 远端主机必须归当前用户拥有、SSH 登录账号支持 sudo，并已经在该 SSH 主机设置中保存正确的 sudo 密码。客户端使用 v17 或更新版本的 `cloudssh.mjs`，运行：

```bash
node cloudssh.mjs jobs run --server <主机ID> --command "id -u" --sudo
```

返回 `0` 才表示该单条命令以 root 身份执行成功。它不是永久 root shell，密码不会传回 Agent。请仅授权可信插件和设备；root 权限理论上可以读取或修改目标主机上的任何文件。
