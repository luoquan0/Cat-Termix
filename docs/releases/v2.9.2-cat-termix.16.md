# Cat-Termix 2.9.2-cat-termix.16 — 共享终端模式与当前 AI 会话恢复

**正式发布成功：2026-10-12 03:05:11 UTC。** 完整源代码、原生 AMD64 / ARM64 容器和 ARM64 更新器测试均通过；GHCR 正式镜像晋升已核实成功。本次仅发布镜像，未直接操作用户正在运行的服务器。

## 修复内容

1. **共享终端模式持久化**：用户在终端 AI「聊天设置」选择「共享终端」后，将执行模式保存到现有 AI 用户偏好 JSON。主动新建对话、进入历史会话、关闭/重新打开 AI 面板、刷新网页后仍继承已选模式；从未启用过的旧用户保持隔离模式。没有真实终端会话句柄的全局 AI 界面继续使用隔离模式，不会凭空获得 SSH 执行权限。
2. **关闭 AI 助手再打开继续当前对话**：保存最后使用的 conversation ID（而不是客户端缓存完整消息）。新挂载的面板通过现有认证 API 读取对话、已保存消息、工具/提案、上下文检查点等信息；下一条消息继续使用同一 conversation ID，而不是新建无关联会话。
3. **按用户及主机隔离**：活动会话指针记录在现有用户级 AI 偏好中，并以宿主机 ID 区分终端侧栏和全局助手；服务端更新指针时验证会话属主及主机。不允许通过另一用户/主机引用或恢复别人的历史消息。
4. **主动新对话和删除历史**：点击「新对话」显式清除当前主机活动会话指针，不会被旧历史自动重新打开；删除历史后服务器清理指向该会话的活动指针，避免重开时指向已删除记录。
5. **并发与持久化**：每个面板串行写入当前会话指针，防止快速切换历史与创建新对话时较旧请求覆盖较新意图。与渠道模型、思考程度、审批状态等原有持久化偏好兼容。现有 SQLite/Postgres/MySQL 的 AI 用户偏好表本就存储 JSON，无需修改数据库结构。

## 软件内更新和验收

备份数据卷、安排 SSH/SFTP 维护时间，然后进入 **管理员设置 → 软件自动更新 → 立即检查 → 立即更新**，等待更新器完成健康检查。主应用更新会中断当前 SSH 会话。

实际验证时，打开某台 SSH 主机的 AI 助手，在「聊天设置」选择「共享终端」，点击「新对话」应继续使用共享模式；再完成一次对话，关闭整个 AI 助手浮窗，再重新打开应恢复刚才的聊天文字且下一条消息仍属于同一个会话。在另一台 SSH 主机打开 AI 助手，不应读取这台主机的会话；主动点「新对话」应打开空会话，不应再恢复旧对话。保存到后端的只是会话 ID，不包含终端会话凭据。

不合并 Termix 上游、不修改原版 `main`。本次**没有直接部署到用户 2244 服务器**；真实服务器、真实 SSH 和终端面板视觉操作仍需要更新后的人工验收。GitHub Releases 页面条目未由 Actions 创建（历史权限限制），但软件更新器读取 GHCR `ai-dev`，不依赖这个页面。
