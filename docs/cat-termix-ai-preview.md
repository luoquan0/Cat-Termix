# Cat-Termix AI Preview 9 测试版

开发分支 `Cat-Termix`，基于 2.9.2，不修改 `main`，也不覆盖 `latest`。测试镜像固定使用 `ghcr.io/luoquan0/cat-termix:ai-dev`；另发布固定版本 `ghcr.io/luoquan0/cat-termix:2.9.2-ai-preview.9`，方便回滚；发布流水线在全部回归、AMD64/ARM64 构建和启动检查成功后才更新该标签。每次发布保留 `sha-<完整提交 SHA>`，镜像版本标签为 `2.9.2-ai-preview.9`。

## Preview 9：本地 Agent 接入（按新版架构实现的测试版）

> **Preview 9 测试部署（仅明确选择才会启用）：** 在独立测试环境中设置 `CAT_TERMIX_IMAGE=ghcr.io/luoquan0/cat-termix:2.9.2-ai-preview.9` 后按既有 Compose 方式部署。现有运行在 `ai-dev` 的 Preview 8 实例保持不变。测试版本不可当作旧版的所有 Agent 特性的完整移植。


保留现有 AI 聊天、软件自动更新和 Preview 8 的所有功能，新增独立「本地 Agent 接入」插件。外部本地 AI 可安装 [cloudssh-agent Skill](../skills/cloudssh-agent/SKILL.md)，沿用 `/agent/v1` 的 Ed25519 设备签名、一次性设备码、网页审批及权限隔离。支持 SSH Jobs、平台/tmux 会话和写入租约，以及 SFTP 列目录、读取、上传、下载、创建目录、移动、删除。设备注册与授权保存到插件自身状态，撤销可阻止后续请求。网页提供配对、主机分类授权、scopes 和设备撤销；不向 AI 聊天工具直接暴露设备管理接口。

管理员可通过「Agent 内网 HTTP」保存可信来源 CIDR（默认禁用 HTTP，优先 HTTPS）。允许来源由真实客户端 IP 与 CIDR 校验，部署环境 `CLOUDSSH_AGENT_HTTP_POLICY_LOCKED=true` 可锁定该策略；不合法的锁定配置拒绝 HTTP。旧本地客户端明文连接仍须显式 `--allow-http`。

**兼容限制：** 旧 CloudSSH 团队项目 ID 与设备批准记录不能直接迁移；此版本用当前账号拥有的主机与文件夹分类构造项目标识，初次连接应重新配对。旧版 `/quick-connections` 临时主机、直接导入密码/私钥创建主机、会话重启后自动恢复远端 tmux、完整的近期 MFA 管理员再次验证、可信内网 IPv6 CIDR 尚未达到旧版完全对等。用户应先在非生产测试主机验证读写操作；不要认为这个预览版本已经完整替代旧仓库的所有边缘能力。

Preview 9 只以已有新版插件系统为基础，旧 CloudSSH 仅作为使用效果参考，不把全部旧 API 或旧项目数据迁移当成发布前置条件。此预览先验证 Linux AMD64 镜像；如需 ARM64 可后续再增加，不影响主功能验收。预览仅发布固定标签 `2.9.2-ai-preview.9` 及 SHA 标签，**不会更新现有 `ai-dev` 滚动标签**，避免意外触发当前已部署实例自动升级。CI 保留原 AI/SSH/更新/回滚回归和 Agent 安全测试，并通过容器内真实 Nginx 验证 Ed25519 设备申请、签名轮询、未批准设备拒绝；真实 SSH/SFTP 仍需独立测试主机验证。
## Preview 8：更新后自动恢复、移除捐赠推广

管理员点击“立即更新”并确认后，浏览器会记住更新请求 ID 和旧版本（不会存储认证密钥），在应用暂时停机时保持轮询。**只有更新器确认新容器健康、修订号发生变化、且新应用的授权更新接口已能访问时**才自动刷新当前网页。刷新后会弹出更新成功通知；只有检查、失败、未发现新版或更新延后时均不会刷新。已启用后台自动安装时，具有更新管理权限的浏览器会在后台低频观察更新阶段，即使关闭系统设置抽屉也能在检测到新版本健康后自动恢复刷新。更新需要断开 SSH，页面刷新会中断未保存的临时编辑内容，请在维护时间操作。

此版本移除用户资料中的 Termix 捐赠广告卡片、定期弹出的捐赠提醒和仪表盘上的捐赠链接；保留原项目开源许可证与版权说明。

**旧版 CloudSSH 本地 Agent：** Preview 9 已通过独立插件开始迁移；未完全对等的功能列于上节，网页 AI 聊天保持独立。

## 独立聊天设置悬浮窗

聊天顶部保留“助手 / 新对话 / 历史 / 设置”，右侧为上下文占用和审批按钮。设置通过 Portal 打开独立小对话框，不再插入聊天消息区或挤压对话高度；可以关闭按钮或 Esc 关闭。模型发现留在聊天组件中运行，关闭设置不取消加载或清空模型。

聊天设置里集中提供商、模型列表与刷新、独立/共用 SSH 执行和上下文压缩。**软件自动更新已移至系统“管理员设置 → 软件自动更新”独立折叠栏目**，位于“常规设置”下方，不再挤占 AI 聊天设置。此入口由插件动态注入，若账号不具备系统管理员和更新管理双重权限则不会显示，即使 AI 助手全局开关关闭也不影响注册。打开窗口、新建对话不会粘贴终端内容，也没有“附加终端输出”按钮。

## 一键免逐次审批

对话右侧的“逐次审批”按钮单击切换“免审批”，再次点击恢复。模式仅作用于当前会话，执行过程中不能切换；新建、恢复另一会话时回到审批模式。按钮提示说明自动执行可能修改服务器。

**免审批不是关闭安全审计、用户权限、主机范围限制或模型服务方的内容政策。** 服务端仍校验权限、记录操作结果，模型不能自行把会话切换成自动模式。

## 自动上下文压缩与占用

默认开启。默认容量 **32768 Token**（仅限尚未识别的模型），回复预留 **4096 Token**，压缩阈值 **75%**，优先保留最近 **4 轮**。现在切换模型时，会从上游提供的模型元数据（例如 OpenAI 兼容网关的 `context_length`、Ollama 的模型详情、Gemini 的输入 Token 上限）自动读取容量，优先采用上游返回的数据；若缺失则仅为**完全匹配的第一方模型 ID**查询随版本维护的官方资料。自定义中转模型（例如 `gpt-5.6-luna`）不根据名称猜测窗口。仍未知就显示“容量未知”并暂按 32768 Token 保守计算。

管理员或用户可直接修改上下文容量；此覆盖值以**登录用户 + 提供商 + 完整模型 ID**保存在数据库，重启、换设备或切换模型后都能恢复，在聊天设置中点击“恢复自动”可清除覆盖值。上游与官方资料的容量均为参考值，中转网关可能有额外限制；自动识别并不保证某个请求一定能容纳相同 Token 数。

占用显示为“上下文 ~百分比”：
`(估算输入 Token + 配置的回复预留) / 配置的上下文容量`。
输入估算计入系统指令、工具定义、历史消息、工具参数/结果以及协议开销；中英文和代码用启发式估算，并非精确 tokenizer。提示中另列上游提供的上次实际输入 Token 数；没有上游 usage 时明确缺省，不将字符估算冒充实际用量。首次请求前显示待统计。

每次模型调用前（包含工具循环）检查预算。超过阈值时，用当前选中模型、禁用所有工具，分块总结较早会话；保存用户目标、主机与路径、约束、执行状态、报错和未完成工作。优先保留最近完整对话轮及成对的工具调用/结果；必要时减少保留轮数并明确精简过长工具回显的中段。最近用户请求不会被静默删除；即便压缩后仍无法容纳，会报错要求调整容量或缩短请求，而不是假装成功。

摘要保存在会话检查点中，刷新/重启可恢复。原始聊天数据库消息不删除。摘要失败、为空、异常请求工具或取消时不覆盖原检查点；每个会话串行处理，避免并发覆盖检查点。上游明确报上下文超限时，只对被拒绝的模型请求尝试一次紧急压缩重试，不重新执行已经运行的命令。压缩会额外消耗模型调用与用量，摘要仍可能丢失细节，应查阅完整历史核对重要内容。

单次任务仍最多 8 轮常规模型调用，压缩调用不计作命令执行轮次；没有固定的聊天消息条数上限，也不声称可无限保留模型记忆。

## 读取终端与两种执行模式

`get_terminal_output` 按需读取当前连接或 `@` 主机的最近终端回显，读取记录可见、结果脱敏，不另开连接，也不把回显伪装成用户消息。只读取登录用户自己的已连接会话并重新校验主机访问权限。多会话不混读、过期明确目标不自动换标签页，读取内容有长度限制。

- **独立执行**：命令走独立 SSH exec 通道，结果在聊天显示，不干扰手动终端。
- **共用当前 SSH 终端**：在当前可见 PTY 中执行，多行脚本的命令与实际输出显示在左侧，输出/退出状态自动回到模型总结。需空闲 Bash/zsh 提示符；不会注入未输入完的命令、前台程序或断线连接。AI 执行时保留输入，Ctrl+C 中断接管。

共用模式用同一 PTY 的前台子 Shell 保护连接，避免脚本中的 `exit`/`exec` 退出父 Shell。继承父 Shell 的目录和环境，脚本内 `cd`/`export` 不永久修改父 Shell；依赖这些状态的操作应组合到同一脚本。

## Docker 自动更新与 HTTP 代理

这里的“上游更新”是**当前部署自动升级本仓库发布的魔改版镜像**，不是自动合并 Termix 原仓库源码。固定跟踪 `ghcr.io/luoquan0/cat-termix:ai-dev`，避免丢失魔改功能。

容器不能在没有宿主机 Docker 控制权限时自行替换。为此提供**独立、明确选择启用的更新器**；应用及 AI 进程不挂载 Docker socket。更新器没有网络控制端口，只读取管理员保存的固定格式配置。

### 首次启用

先保留原数据、环境变量和端口配置，并更新部署目录中的两个 Compose 文件。标准示例使用同一个 `cat-termix-ai-data` 数据卷：

```bash
git switch Cat-Termix
git pull --ff-only origin Cat-Termix
# 跟踪滚动测试版；不要继续使用旧的 sha 固定标签。
export CAT_TERMIX_IMAGE=ghcr.io/luoquan0/cat-termix:ai-dev
docker compose -f docker-compose.ai-test.yml -f docker-compose.ai-updates.yml pull
docker compose -f docker-compose.ai-test.yml -f docker-compose.ai-updates.yml up -d
```

随后进入**整个系统的管理员设置 → 软件自动更新**，保存间隔、代理并按需开启“自动安装”。默认关闭自动安装；支持“立即检查”和确认重启后的“立即更新”。管理员需要 `ai.manage_updates` 和 `admin.settings.manage` 两项权限。软件更新接口不是模型工具，自动执行模式不赋予更新权限。

点击“立即检查”后，按钮和系统设置栏目标题出现旋转图标，并显示“请求已排队 → 正在连接 GHCR → 检查完成/找到新版本/检查失败”的实时进度；更新器异步检查可能先排队约 15 秒。页面关闭后重新打开仍可从后台请求编号恢复检查状态；请求超时、更新器失联或版本检查失败会给出相应反馈，绝不把 HTTP 202 接受请求当作完成检查。繁忙状态约每 2 秒刷新，空闲约每 10 秒刷新，页面显示真实上次检查时间与当前/已发布构建。代理请求失败会显示更新器的脱敏错误消息。此功能只需更新主应用镜像，不要求重建已经部署的旧更新器。

默认检查间隔 6 小时，可设 1–168 小时。更新会重启应用并断开 SSH。正在运行的 AI 请求会延后更新，并通过维护握手阻止停机前的新 AI 执行；普通手动 SSH 会话仍会因升级断开，请安排维护时间。

### 代理与验证

代理支持 `http://` 和 `https://`，例如 `http://host.docker.internal:7890`。**版本清单、认证和镜像层下载都通过更新器的代理**，不依赖 Docker daemon 的代理环境变量；TLS 校验保持开启。支持 URL 编码的代理认证信息，保存后不回显密码、不写入日志。代理仅影响更新，不修改 AI 上游配置。

只接受指定 GHCR 仓库的 Linux AMD64/ARM64 镜像，核对源码/提交标签、镜像配置摘要、压缩层和解压层摘要，再通过 Docker API 导入本机。

### 备份与失败处理

只自动替换明确标记的同一 Compose 项目中唯一的 Cat-Termix 容器。保存端口、卷、环境、重启策略和网络别名。只支持标准 bridge 网络、持久 `/app/data` 和本地 SQLite；外部数据库、自定义数据路径、静态容器 IP、特权或自动删除容器会拒绝自动替换，需另行安排备份/迁移。

停机后先做完整本地数据冷备份，再替换容器；新容器通过健康检查才清理旧容器。启动失败时恢复冷备份与旧容器，保留最近 3 份备份，不删除应用数据卷。升级维护窗口期间不要产生新业务写入，失败恢复会回到冷备份时点。

若更新器/宿主机在维护中异常掉电，保留维护日志与冷备份并暂停后续自动更新，不猜测数据状态继续替换。检查更新器的 `/state/journal.json`、`/state/backups/` 和带 `.rollback-` 后缀的旧容器，完成恢复后再移除维护日志。

**Docker socket 相当于宿主机管理权限。** 虽然只有独立更新器挂载它，仍应保护更新器镜像、管理员账号和控制卷，不把 socket 开放到网络。使用自定义绑定目录的部署必须把更新器的 `/backup-source` 调整到同一个真实数据源，代码会核对两边 mount，防止备份错误数据卷。更新器本身作为稳定辅助服务不自动替换自身；未来涉及更新协议变化时需在维护窗口同步更新辅助服务。

## 验证与部署注意

运行 AI/SSH/核心回归；增加压缩失败/取消/协议配对/预算测试、独立弹窗与一键切换测试、更新代理/摘要核对测试，以及真实 Docker 冷备份、容器替换、失败回滚测试。发布仍需双架构容器启动检查。

默认测试地址 `http://localhost:9080`，默认仅绑定本机。需要局域网访问时沿用既有 `CAT_TERMIX_BIND`/端口设置，并限制网络入口。更新后强制刷新网页并重新打开 SSH 会话。自动化验收不等于已连接用户的实际模型网关或 SSH 主机实测。
